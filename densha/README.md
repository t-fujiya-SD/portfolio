# でんしゃすごろく

4歳の電車好きの子と、大人が同じ盤で本気で遊べるように作った知育すごろく。
桃鉄の「サイコロ → 分岐 → 物件 → 決算」という骨格に、**ほんものの路線・種別・乗り換え**を載せてある。

🔗 https://spicy-device.com/densha/

iPhone / iPad の Safari で開いて「ホーム画面に追加」すると、全画面のアプリとして動く。
インストール不要・オフライン動作・App Store 申請不要。

---

## 設計の中心：同じ操作に二層の意味を持たせる

4歳は漢字が読めず、集中は10分、負けると続かない。一方で「E233系7000番台」や
「湘南新宿ラインの特別快速」は大人の楽しみ。この2つは正面衝突する。
そこで**操作は1つ、意味は2つ**にした。

| 操作 | 子供が見ているもの | 大人が見ているもの |
|---|---|---|
| 駅に止まる | スタンプを押す（🍜 えきそば / 🥐 パンやさん …） | 物件購入。駅の乗降客数が収益係数 |
| 3ターンごと | 「おこづかいの日！」 | 決算。新宿・池袋を持っていると効く |
| 分岐で電車を選ぶ | 色を選ぶ（緑 / 水色 / オレンジ） | 種別・向き・乗換コストの最適化 |
| サイコロを振る | 数を読む | 各停で3駅 vs 快速で1目5駅のジレンマ |
| 目的駅に着く | 車両カードがもらえる | 番台違い・直通車両のコレクション |

「おとなモード」を入れると、漢字・正式な形式名・乗車人員の概算が表示に切り替わる。

## ルール

- **サイコロ1個（1〜6）= 使える「目」**。目は次の2つに使う。
  - `すすむ` … いま乗っている電車の **次の停車駅** へ 1つ進む（目 1）
  - `のりかえ` … 別の電車に乗る（目 1）
- **だから種別が効く。** 快速や急行は通過駅を飛ばすので、同じ目でずっと遠くへ行ける。
  例）新宿 → 小田原は、各駅停車なら14駅ぶん、特急ロマンスカーなら **4駅ぶん**。
- **向きを変えるのも「のりかえ」1**。終点に着いたら反対向きの電車に乗り換える。
- **直通運転の乗り換えは 0**。電車を降りないから。
  例）埼京線 → りんかい線（大崎）、埼京線 → 相鉄線（大崎）、宇都宮線・高崎線 → 東海道線（東京）。
  これがそのまま「直通は得」という体験になる。
- ターンの終わりに止まった駅でスタンプ（物件）を買える。**3ターンごとに決算。**
- 目的駅に着くとボーナスと車両カード。そこで一休みするので、次の乗り換えは 0。
- **スコア = 手持ちコイン + 残りターン × 8。**
  制限ターンは子供が負けないよう緩めにしてあり、大人はスコアで競う。
  「新宿を買いに1ターン寄り道する」か「早着ボーナスを取る」かが実際のジレンマになる。

### 画面
メインは**首都圏全体の路線図**。実際の緯度経度で並べてあるので、大宮は北、横浜は南、
八王子は西、千葉は東に出る。都心は駅が密集して潰れるため、中心からの距離を `^0.55` で
引き伸ばす魚眼をかけている（実際の広域路線図と同じ処理）。

- **いま乗っている路線だけが濃く太く**、ほかの路線は薄くなる。これで「何線に乗っているか」が盤面で分かる
- 自分のコマ 🚃、目的駅の 🚩、買ったスタンプの絵柄が地図上に出る
- 指でドラッグして移動、ピンチで拡大。🚃ボタンで自分の位置へ、🗾ボタンで全体表示
- 駅名ラベルは重なると読めないので、優先度（現在地 > 目的地 > 所有駅 > 乗降客数）の順に
  置いて、ぶつかるものは表示しない。4方向に逃がしてから諦める
- 地図の下には**車内の路線図と同じ横長のストリップ**も出る。地図では描けない
  「この電車が通過する駅」を小さい点で示すため
- 画面が広いときは 地図を左・操作を右の2列になる

### ヒント
💡 ボタンは、いまの駅・いまの電車・いまの向きから目的駅までの**最短手順を実際に探索して**、
次の一手を日本語で言う（「埼京線の快速、大崎ゆきに のりかえよう。あと3かいで つくよ」）。
最短の一手には 💡 が付く。設定でオフにすると大人向けの難易度になる。

## 忠実度について（簡略化した点）

正確に作った部分と、意図的に省いた部分をはっきり分けている。

**再現したもの**
- 路線ごとの実際の駅順と、種別ごとの停車・通過パターン
- 埼京線が川口を通らないこと、快速アーバンが尾久を通過することなど、乗り換えの形を決める事実
- 相鉄・JR直通線、りんかい線直通、上野東京ラインの直通関係
- 車両の形式と番台（E233系1000/3000/5000/7000番台、E231系0/500/1000番台、相鉄12000系、りんかい線70-000形、小田急70000形GSEなど）と、実際に走る路線の対応

**省いたもの**
- **時刻表・ダイヤ**は入れていない。停車パターンだけを持つ。入れると開発量が10倍になるうえ、遊びとしての面白さはほぼ増えない。
- 停車パターンの細部（時間帯変動、土休日ダイヤ、一部の通過駅）は簡略化している。
- 一部の中間駅を省略している（高崎線の吹上・行田など）。
- 乗降客数は**概算**。駅の規模感を収益係数として再現するための値で、厳密な実数ではない。
- **車両の写真・ロゴ・社章は一切使っていない。** 著作権・商標の問題があるため、すべてパラメータから描いた自作のSVG（車体色・帯・前面）。4歳は「顔が黒くて帯が水色」で識別できるので、実用上これで足りる。駅名・路線名は事実表記。

## 技術構成

ビルド不要の静的ファイル4つだけ。GitHub Pages にそのまま乗る。

```
/densha/
  index.html            画面構造とCSS
  data.js               路線・駅・種別・車両・ミッション・駅の座標
  engine.js             路線グラフと経路探索（0-1 BFS）
  map.js                全体路線図（投影・魚眼・並走路線のずらし・パン/ズーム）
  ui.js                 描画とゲーム進行
  manifest.webmanifest  ホーム画面追加用
  icon-180.png / icon-512.png
```

- **経路探索**：乗り換えコスト0（直通・種別変更）と1（通常の乗り換え）が混在するので、
  ダイクストラではなく **0-1 BFS** で解いている。状態は `(駅, 路線, 種別, 向き)`。
  「最初の一手」をタグとして伝播させることで、ヒントも**1回の探索**で求まる（約100ms）。
- **出発時の向き**は、目的地までの最小コストが小さい電車を選ぶ。
  ここは乗車コストを実費（0ではなく1）で評価しないと、反対向きの電車が同点になってしまう。
- **全体路線図**は、緯度経度を等角に近い形で平面に落としてから、中心からの距離に
  `r^0.55` の魚眼をかけている。方角を保ったまま都心の密集をほどける。
  同じ区間を複数路線が走るところは、区間ごとに「その区間を使う路線」を数えて
  垂直方向に等間隔でずらす（249区間）。文字とコマは拡大率と画面幅の両方で
  割り戻して実寸を一定に保ち、パン・ズームは `<g>` の transform だけを
  書き換える（1回 0.25ms 程度で、毎フレーム描き直さない）。
- **車内の路線図ストリップ**も併置した。地図では表現しにくい「この電車が通過する駅」を
  小さい点で示すため。4歳が実際に電車の中で見ているものと同じ形。
- **読み上げ**は Web Speech API（`ja-JP`）。駅名・種別・行先・ヒントを読む。
- **音**は Web Audio の簡易シンセ（発車・到着・乗り換え・コイン・ファンファーレ）。音声ファイルなし。
- **保存**は localStorage（車両図鑑・ミッションごとの最高スコアと★・設定）。
