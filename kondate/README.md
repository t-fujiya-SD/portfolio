# 月曜はお魚です — 平日5日の献立・買い物・常備品

平日だけ自炊する家庭のための単一HTMLアプリ。
**土曜に提案 → 日曜朝までに承認 → 日曜に買い物 → 平日に作って評価** という1週間のサイクルを回します。

```
土 12:00  来週の献立が自動で提案される（主菜＋副菜）
   ↓      承認 / 差戻し / その他
日 08:00  承認の締切
   ↓      承認した日の食材だけが買い物リストに並ぶ
日 09:00  リストを見ながら買い物（タップで線が引かれる）
   ↓      買い物おわり → 常備品の購入日を更新・サイクルを学習
月〜金    作って食べる。任意で 👍😐👎 を押す
   ↓      評価は次回の提案スコアに反映される
土 12:00  次の週へ
```

## 曜日ごとの決め方

曜日ごとに3つのルールから選べます（設定 → 曜日ごとの決め方）。

| ルール | 動き | 初期設定 |
|---|---|---|
| **ローテーション** | 選んだ順にぐるぐる回す。前の週に出たものの次が出る | **月** ししゃも → 赤魚の煮付け → ホッケの塩焼き |
| **定番から選ぶ** | 決めた候補の中から、最近出ていないものをランダムに選ぶ | **金** チキントマト煮 / ビーフストロガノフ / 無水チキンカレー |
| **気分** | 全レシピから自動で選ぶ | **火・水・木** |

**曜日の割り当てはレシピを書くその場でできます。** レシピの登録・編集フォームに
「出す曜日」（おまかせ／月〜金）があり、曜日を選ぶとその曜日の専用枠に入ります。
「気分」ルールだった曜日に最初の1品を割り当てると、その曜日は自動的に
「定番から選ぶ」に切り替わります。月曜のようにローテーションの曜日へ割り当てると
順番の最後に追加されます。設定画面の曜日ルールと同じデータを編集しているだけなので、
どちらから触っても矛盾しません。

**ローテーション・定番に割り当てたレシピは、その曜日の専用枠です。**
「気分」の日（火〜木）の候補には出しません。月曜の魚が水曜に来たり、
金曜の定番が火曜に来たりしないためです。差戻しで引き直しても同様です。
レシピ一覧には「月ローテ」「金定番」のバッジが付きます。

「気分」の日には次のルールが効きます。

- 同じ料理を2日連続にしない（絶対）
- 同じタンパク源（肉／魚／その他）の2日連続は、なるべく避ける（減点。絶対ではない）
- 傷みやすいもの（魚→肉→その他）を、少しだけ週の前半へ
- 最近出たもの、評価の低いものは出しにくい。4週以上出ていないものは横並びで、そこから先はランダム
- 週に魚を最低1回
- 「余っている食材」に登録したものを使うレシピを優先

### 品数が足りないときは日を空ける

**同じ料理を連日は出しません。これだけは絶対の制約です。**
たんぱく源の連続（別の料理だが両方とも肉）は、レシピが偏っていれば妥協します。
しかし同じ料理の連続は妥協せず、**置けない日は「未定」のまま空けます**。

品数が足りないときは、**その週にまだ出ていない料理を優先し、それでも足りない日だけ
隣り合わない日での使い回し**を許します（気分の候補が1品なら、火・木に出して水は空ける）。
承認ずみの日の料理も「使い回し」として扱います。以前は週全体の使用済みとして除外していたため、
火曜に承認した唯一の候補を、離れた木曜にも置けるのに日が空いていました。
外食・残り物・作らない日にした日の料理は、使用済みに数えません。

**気分の候補が0品でも、ローテーション・定番のレシピには戻しません。** 以前は全主菜に戻していたため、
全主菜を月・金に割り当てると月曜の魚が火〜木に出ていました。足りない日は空けて、献立タブに
理由と対処（自分で書く／レシピを足す）を出します。

連日おなじものを並べるくらいなら、空欄のほうが正直で、手も動きます。

### 同じものばかり出さないために

**「最近出た」は、前の週までの献立に載った日で数えます。** 承認していない提案も含みます。
以前は「承認した日が過ぎた」ときの調理記録だけで数えていたので、承認しない使い方だと
いつまでも「まだ出していない」扱いになり、同じものが毎週出ていました。

**ローテーションは、前の週にこの曜日で出たものの次を出します。**
以前は「買い物おわり」を押したときにしか進まず、押さない週があると毎週同じ魚でした。
いまは「買い物おわり」ではローテーションを動かしません。

**次に出す料理は、設定の曜日ルールの「1つ進める」で手動で決められます。**
手動の指定は、**料理の id と「どの週から有効か」**で持ちます（データ上は `manual: {recipeId, effectiveFromWeek}`）。

- 有効になるのは、**日付が今日以降で、まだ承認していない最初のその曜日**の週から。
  保存した時点でその日が未承認ならすぐ差し替えます（過ぎた曜日や承認ずみの日は書き換えない）
- 指定した料理が、有効な週以降にその曜日で実際に入ったら消化。以後は通常の順番（その料理の次）に戻る
- 有効な週より前の週を提案し直しても、指定は効きません
- 指定した料理を削除したり、ローテーションから外したりしたら、指定は消えて通常の順番に戻ります
- 設定を開いて保存しただけでは指定になりません（「1つ進める」を押したときだけ）

以前は「何番目か（next）」と「設定した日（nextSetAt）」で持っていたため、
同じ日に承認ずみだと翌週に効かない、過去の週の「買い物おわり」で上書きされる、
レシピを削除・並べ替えすると別の料理を指す、平日に保存すると過ぎた月曜まで書き換わる、
といった不具合がありました。古い形式は読み込み時に新しい形式へ移します（データ形式 v3）。
前の版で「まだ効いていた」指定だけを引き継ぎます。

**たんぱく源の連続は、絶対禁止から減点に変えました。**
以前は「同じたんぱく源を2日続けない」を絶対の条件にしていました。すると月＝魚・金＝肉で両端が
決まっていると、木曜には肉以外しか置けません。気分の日に出せる「その他」の料理が2品しかないと、
**その2品が毎週かならず入る**状態になっていました。毎週同じ顔ぶれよりは、
たまに肉が2日続くほうがまし、という判断です。同じ料理の連続は今までどおり禁止です。

**評価（👍）の効き方は弱めています。** 強いと、👍の料理が毎週出続けます。

**「提案」を押し直すと変わります。** 押し直したときは、いま出ている料理を少し出にくくします
（ローテーションの曜日は、その週の順番を守るので変わりません。1日だけ変えたいときは差戻し）。

**ローテーションの曜日で差戻しすると、今の料理の次へ1つずつ進みます。**
以前は差戻しのたびに「その週の番」から探し直していたため、番がホッケの週は
ホッケ → ししゃも → ホッケ → ししゃも…と2品を行き来するだけで、赤魚に届きませんでした。

**差戻しの候補は、どれも前後の日と同じ料理にしません。** ローテーション・定番の曜日は
そのルールの中だけで探し、代わりがなければ今の料理のまま「ほかに出せるレシピがありません」と出します。
以前は、気分の候補が1品だけだと差戻しで3日連続になったり、ローテーションが1品だけだと
差戻しで気分の料理や別の曜日の料理に変わったりしていました。

8週間を再現して比べた結果（月＝ローテーション5品、金＝定番3品、気分の日の主菜7品）:

| | 以前 | 現在 |
|---|---|---|
| 月曜の種類（買い物おわりを押さない使い方） | 1種類 | 5種類 |
| 火〜木が前の週とかぶった数 | 毎週2品が固定 | 21品中2〜4品 |
| 同じ週で「提案」を8回押し直す | 水曜だけ変わる | 8通り |

### 配置アルゴリズム

空いている曜日を日付順に1日ずつ埋めます。各曜日で、前日と（決まっていれば）翌日を見て、
点数（最近出ていない度合い＋評価＋余り食材＋ランダム）から、たんぱく源の連続と
傷みやすさを加減した候補を選びます。これを少しずつ揺らして6回組み、いちばん点の高い
組み合わせを採ります。主菜が平日5日ぶんに満たない場合は使い回しますが、連続はさせません。

ローテーション・定番の曜日は、そのルールに候補があるかぎりルールの中だけで選びます
（候補が全部しまわれていれば「気分」と同じ扱い）。

## 副菜

各日に主菜＋副菜を提案します（設定で 0／1／2品）。
主菜と食材がかぶらないもの、手早くできるものを優先します。
初期状態で副菜20品（おひたし・冷奴・味噌汁・きんぴら 等）が入っています。

いつ作ったかはレシピ一覧に出ます（「◯日前」「通算◯回」）。
副菜は献立カードからタップで差し替え・追加・削除できます。

## 承認・差戻し・その他

| ボタン | 動き |
|---|---|
| **承認** | その日の食材が買い物リストに載る |
| **差戻し** | 別の案に引き直す（曜日ルールは尊重される）。未承認のまま。代わりが無ければ今のまま |
| **その他** | 外食 / 残り物 / 自分で主菜を選ぶ / 提案に戻す |

**未承認の日の食材は買い物リストに出ません。** 買い物タブに残り日数が警告として出ます。

## 評価

平日、その日のカードで 👍 また作りたい / 😐 ふつう / 👎 いまいち を任意で押せます。
同じボタンをもう一度押すと取り消し。評価はレシピごとの平均として集計され、
次回以降の提案スコアに反映されます（👍で出やすく、👎で出にくく）。

**「作った」ボタンは押させません。** 承認した日は、その日を過ぎた時点で自動的に調理済みとして記録されます。
評価はあくまで任意の上乗せです。

## 解いている課題

| 面倒 | 仕掛け |
|---|---|
| 毎週の献立を決めるのがしんどい | 土曜に1週間ぶんが自動で出る。承認するか差し戻すかだけ |
| 決めたあと必要な食材を覚えていられない | 承認した時点で買い物リストが完成。各食材に「何曜日の何に使うか」が付く |
| 常備品の在庫と買い忘れ | 在庫を数えない。「買った日＋目安サイクル」から切れる時期を推定してリストに載せる |

## 設計上の判断

**分量はレシピ側で管理しない。** レシピの分量（玉ねぎ 1/2個）と店で買う単位（3個入りネット）が
違うため、足し算しても結局その場で人が判断することになります。代わりに
**「何曜日の何に使うか」** を出します。分量入力が不要になるぶん、レシピ登録が1品20秒で済みます。

ただしこの判断には **「判断できる人が店にいる」** という前提がありました。
買い物は基本どちらか一人が行くので、その前提は成り立ちません。
そこで、**迷った食材だけその場でメモを残せる**ようにしています（後述）。
全レシピに分量を入れる作業には戻らず、実際に迷ったものだけが埋まっていきます。

**在庫は数えない。** 「卵を1個使った」を毎回記録する運用は続きません。
記録するのは「買った」の1回だけ（買い物タブの「買い物おわり」で、チェックした常備品に自動で付きます）。
実際に見て残っていたら「まだある」、少なくなっていたら「次買う」を1タップ。
そのズレからサイクルを自動補正するので、初期値が雑でも1ヶ月で実態に寄ります。

**店の中の動きまで面倒を見る。** 買いすぎ・買い忘れは「何を買うか」だけでなく
「店でどう動くか」で決まります。売り場の順番を店に合わせ、置き場所を覚え、
日もちしないものを別枠に切り出すのは、どれも **店で迷う時間を削る** ための同じ一手です。
迷っている時間が長いほど、関係ないものが目に入って買い物かごに増えます。

**「今日は作らない」を最初から入れる。** 平日5日が必ず自炊とは限りません（外食・残り物）。
「その他」にした日の食材は買い物リストから消えます。

## レシピの取り込み

**URLを貼るだけ**でも、**材料欄・概要欄のコピペ**でも取り込めます。

### URLからの取り込み

ブラウザは他サイトを直接読めない（CORS）ため、公開の読み取り中継サービス
（allorigins → r.jina.ai → corsproxy の順にフェイルオーバー、各12秒でタイムアウト）を
経由してページを取得します。取得後は精度の高い順に3段構えで抜き出します。

1. **schema.org/Recipe の JSON-LD** — クックパッド・クラシル・ナディアなど大半の
   レシピサイトが埋めている機械可読データ。`recipeIngredient` から材料、`name` から
   料理名、`totalTime`（ISO 8601）から所要時間を取ります。`@graph` 内や配列も探索します
2. **YouTube の概要欄** — ページ内JSONの `shortDescription` を取り出してテキスト解析。
   料理名は概要欄の1行目（挨拶のことが多い）ではなく動画タイトル（og:title）を優先します
3. **本文テキスト** — タグを落として既存の貼り付けパーサーに通します

あわせて**作り方と元レシピのURLも保存**します。JSON-LDの `recipeInstructions`、
YouTubeなら概要欄の【作り方】以降（チャンネル登録などの宣伝の手前まで）を切り出します。
作る日は「今日の献立」の **📖 作り方** から、食材・手順・元ページへのリンクが見られます。
手順は編集フォームの「作り方メモ」でいつでも直せます。

**同じURL・同じ料理名を取り込み直すと、新規ではなく既存レシピの上書き更新になります。**
評価・作った回数・曜日の割り当てはそのまま引き継がれるので、
作り方を取り直したいときは同じURLを貼り直すだけで済みます（削除は不要）。

中継が全滅した場合は、従来どおり材料欄のコピペを案内します。
URLは公開の中継サービスに送られます（レシピページのURLのみ。アプリのデータは送りません）。

### 貼り付けパーサー

コピペの場合は貼ったテキストから食材だけを抽出します。

- `材料` `【材料】` を検出し、`作り方` `手順` `http` などが現れるまでを材料ブロックとして切り出す
- 箇条書き記号（`・` `-` `■` `①`）、区切り（`…` `：` タブ）、分量（`200g` `1/2個` `大さじ2` `適量`）を除去
- 常備調味料（醤油・みりん・ごま油・豆板醤・鶏がらスープ…）は自動で除外
- 残った食材を売り場カテゴリ（野菜／肉／魚／豆腐卵乳／乾物麺／調味料／冷凍／日用品）に自動仕分け
- 魚が含まれれば「魚」、肉なら「肉」とタンパク源タグを自動判定
- 料理名と所要時間（`15分`）も推測
- 最後に確認画面。主菜／副菜の切替、カテゴリは絵文字タップで変更、不要なものは `✕` で削除

クックパッド系（タブ区切り）、YouTube概要欄（`・食材…分量`）、`名前：分量` 形式、食材の羅列のみ、で動作確認済み。

> URLだけを貼っても取り込めません。ブラウザから他サイトの中身を直接読めない（CORS）ためです。
> ページを開いて材料欄をコピーしてください。

## この順番で育てる

レシピを先に揃えなくても回るようになっています。

```
週次の買い物リスト
  月〜金の献立を書く（レシピ未登録でも料理名だけでOK）
  買うものを足す → 何に使うか（料理名 / 娯楽 / 日用品 / 常備）
        ↓
  記録が貯まる（📊 記録タブ：料理別に食材と回数が集まる）
        ↓
  「レシピにする」で、その料理のレシピが自動で立ち上がる
        ↓
  URLの貼り付けや編集で作り方・所要時間などを仕上げる
        ↓
  献立の自動提案・買い物リストの自動生成が効きはじめる
```

### 予定（📅 カレンダー）

献立を考えるときに「その日どちらかが不在か」が見えるように、日付ごとのメモを持てます。

- ヘッダーの 📅、または曜日カードの日付欄をタップでカレンダーが開く
- 日付をタップして自由文で書く（例：`おじ 夜仕事`、`保育園おやすみ`）。1日に何件でも
- 書いた予定は**その日の献立カードの一番上**に出る。今日の表示と買い物タブの献立バーにも出る
- 誰が書いたかが残る（設定の「この端末の名前」）。共有していれば相手の端末にも出る
- カレンダーには祝日が赤、予定のある日に点が付く

### 祝日は作らない

平日だけ自炊する前提なので、**日本の祝日は自動で「作らない」**になります。
祝日は計算で判定するため、毎年の手入力は不要です。

- 固定の祝日、ハッピーマンデー（成人・海・敬老・スポーツ）
- 春分の日・秋分の日（1980〜2099年で有効な近似式）
- 振替休日（日曜と重なったとき）、国民の休日（祝日に挟まれた平日）

判定は開くたびに走ります。**明示的に「作る」と言った日だけは触りません。**

| 日の状態 | 祝日が来たら |
|---|---|
| 未承認（提案で入っただけ／空） | 祝日にする |
| 承認ずみ | そのまま（作る日として尊重） |
| 「この日は作ることにする」を押した日 | そのまま |
| 外食・残り物にした日 | そのまま |

承認や「この日は作ることにする」を押すと、その日に**作ると決めた印**が付くので、
リロードや同期をしても祝日に引き戻されません。「その他 → 作らない」で戻せば印も消えます。
設定でこの挙動ごとオフにもできます。

例：2026年9月21〜23日は 敬老の日・国民の休日・秋分の日 なので、その週は木・金だけが対象になります。

### 曜日ごとの入力

レシピの登録・編集フォームの「出す曜日」は**複数えらべます**（木と金の両方、など）。
「おまかせ」で全部外れます。選んだ曜日ごとに、そこに既にいる仲間（ローテーションの順番や
定番の顔ぶれ）がヒントに出ます。曜日から全部外れたルールは自動で「気分」に戻ります。

曜日カードの料理名か ✏️ をタップすると、先頭に**「新しいメニューを書く」**が出ます。
ここから2つのルートを選べます。

| | 動き |
|---|---|
| **この日に置く** | 料理名だけをその日に置く。買い物メモを紐づけていけば、あとで記録からレシピに起こせる |
| **レシピとして登録** | 続けて食材・所要時間・作り方（URLの貼り付けも可）まで入れる。保存するとその日に自動で入る |

下に登録ずみのレシピも並ぶので、そこから選ぶこともできます。

**献立は料理名の直接入力に対応**しています（📖 レシピが1件も無くても書けます）。
書いた料理名は買い物メモの紐づけ候補として最優先で出るので、
「月曜：鮭の塩焼き」と書いてから鮭と大根を足す、という順で記録が貯まります。

買い物タブの先頭にその週の月〜金が並び、**タップするとその料理の食材をまとめて足せます**。
献立カードには、その料理に紐づいた買い物メモがそのまま表示されます。

記録からレシピを起こすと、**同じ料理名で直接入力していた日が自動でそのレシピに差し替わります**
（その日に付けていた評価もレシピへ引き継ぎます）。

## 買い物の記録（📊 記録タブ）

レシピを先に登録するのは手間がかかるので、**先に買ったものを2人で書き留めていき、
貯まった記録からレシピを起こす**という逆向きの使い方ができます。

買い物メモの1件ごとに「何のために買ったか」を持たせます。

| 用途 | 例 | 判定 |
|---|---|---|
| 🍳 料理 | 豚ひき肉・春雨（麻婆春雨用） | 料理名を紐づける |
| 🧊 常備 | 調味料など | 自動 |
| 🍺 娯楽 | ビール・お菓子・アイス | 自動（辞書判定） |
| 🧴 日用品 | トイレットペーパー | 自動（売り場カテゴリ） |

食材は用途が一意に決まらないため、あえて**未分類**で入ります。記録タブに件数が出るので、
1タップで料理に紐づけます（最近つかった料理名がチップで出るので入力はほぼ不要）。

### 入力

買い物タブの上部に入力欄があり、**品名を打つ → 何用かのボタンを選ぶ**だけです。

```
🛒 買うものを足す
[ 品名（例）豚ひき肉、ビール、ゴミ袋 ]
何に使う？（選んだまま続けて足せます）
[木 ほっけ] [金 ハヤシライス] [🧊常備] [🍺娯楽] [🧴日用品] [🍳別の料理…] [おまかせ]
[          リストに追加          ]
```

- その週の献立に書いた料理が**曜日つきのボタン**として並ぶので、タップするだけで紐づきます
- **選んだ用途は保持される**ので、「木 ほっけ」を選んだまま食材を続けて打てます
- 「おまかせ」は自動判定（日用品・嗜好品は当たる。食材は未分類になる）
- 「別の料理…」は献立に無い料理名を打つとき

### 記録タブ

今週 / この1ヶ月 / 全期間で切り替えて、用途の内訳（積み上げバー）、未分類の仕分け待ち、
**料理別の一覧**（何回作ったか・使った食材と回数）、娯楽・日用品・常備の一覧を表示します。

### 記録からレシピを起こす

料理別の一覧の「レシピにする」で、その料理に紐づいた食材を全期間から集計し、
出現回数の多い順に並べてレシピの確認画面を開きます。調味料は自動で分けられます。
同名のレシピが既にあれば上書き更新になります（評価・曜日の割り当ては引き継ぎ）。

記録は**400日ぶん**保持します（当初は70日で間引いていたため、2ヶ月ぶんを貯める用途では
ちょうど使う頃に消え始める問題がありました）。

### 誰が足したか

設定の「この端末の名前」を入れておくと、メモに記録されます。
この設定は端末ごとで、共有されません。

## 買い物リスト

スーパーの売り場順（既定は 野菜 → 肉 → 魚 → 豆腐卵乳 → 乾物麺 → 調味料 → お菓子 → 冷凍 → 日用品 → その他）に並びます。
タップすると線が引かれます。献立の食材と常備品が同名の場合は1行にまとめます。
「📋 コピー」で献立＋未購入リストをテキスト化できます。

### 売り場をまわる順（⚙️ 設定）

既定の並びは一般的なスーパーの配置ですが、店によって違います。
設定の「売り場をまわる順」で ▲▼ を押すと、カテゴリの順番を入れ替えられます。
**いつも行く店を歩く順に合わせると、上から順に取っていくだけで買い物が終わります。**
行をタップすると、その売り場が店のどのあたりかも書けて、買い物リストの見出しに 📍 で出ます。

行ったり来たりしないことには二重の効き目があります。歩く距離が減るのと、
目的の売り場以外を通らないので **目に入って買ってしまうものが減る** ことです。

#### 📷 案内図の写真から読み取る

順番と場所を言葉で入れるのは面倒なので、**店の売り場案内図を1枚撮れば済む**ようにしました
（APIキーが要ります）。Claude が順路と各売り場の位置を読み、

- 結果は**そのまま適用せず**、並びを見せて「これにする / やめる」を選ばせます
- 写真に写っていないカテゴリも、一般的な配置から推測して順番には入れます
- 売り場と関係ない写真なら何も変えずにそう言います

### ⏰ 直前に買うもの

鍋の野菜、刺身、もやしのように日もちしないものは、日曜にまとめ買いすると
使う日には傷んでいます。食材の ✎ から「買うタイミング → ⏰ 直前に買う」にすると、

- 売り場ごとのグループから外れ、リストのいちばん上の **⏰ 直前に買う** 枠にまとまる
- 「木曜に必要」と、**何曜に要るか**が付く（献立の日付と用途タグから出しています）

日曜の買い物では飛ばし、必要な日の前に寄って買う、という前提の枠です。
チェックは普通に付けられるので、そのまま買っても問題ありません。
設定は食材名に紐づくので、一度決めれば翌週からも自動でこの枠に入ります。

### 📍 売り場メモ

同じく ✎ から「入口すぐ左」「奥の冷蔵ケース」のような置き場所を書けます。
書くと毎週 📍 付きで行に出ます。**一度探したものを二度探さないため**の仕掛けで、
買う量のメモと同じ積み上げ方です。

### 行を消す

どの行にも ✕ があります。出どころによって動きが変わります。

- **自分で書いたメモ** … その場で削除（記録なので、書き間違いは消えるのが正しい）
- **献立の食材・常備品** … 今週のリストから外すだけ。下の「🗑 消したもの」から戻せる

献立から出ている食材を毎週消すことになるなら、献立側で副菜を外すほうが根本的です
（曜日カードの副菜の ✕）。

### 食材の設定（一人で買いに行くための仕掛け）

各行の ✎ で開くシートに、その食材について覚えておくことを3つ書けます。

| 項目 | 例 | 出かた |
| --- | --- | --- |
| 買う量のめやす | 3個入りネット / 大きめ1本 | 品名の横に小さく |
| 売り場 | 入口すぐ左 / 奥の冷蔵ケース | 品名の横に 📍 付きで |
| 買うタイミング | 日曜にまとめて / ⏰ 直前に買う | ⏰ はリスト最上部の専用枠へ |

**どれも食材名に紐づいて覚えるので、翌週以降もずっと表示されます。**
一度迷ったものは二度と迷わない、という積み上げ方です。
よく使う単位はワンタップで入ります。「消す」で3つまとめて解除できます。

### 買い物中に相手が足した品

同期で買い物リストに増えたぶんがあれば「相手が追加：ビール、シャンプー」と知らせます。
黙って行が増えると、スクロールして見ている最中に見落とすためです。
自分で追加したものでは鳴りません。

## 値段（🧾 レシート）

買い物リストには「何を買ったか」がもう全部あります。足りないのは値段だけなので、
**リストの行に金額を入れるだけ**の画面にしました（買い物タブのいちばん下 → 🧾 レシートを登録）。

記録すると、次の週から各行に出ます。

- まだ買っていない → `前回 ¥198`（**レジに並ぶ前に高いか安いか分かる**）
- この週に記録ずみ → `¥178 ▼¥20`

買い物は日曜に行き、週は月曜はじまりなので、**週の起点は2日前に取って**
日曜に買ったぶんが「先週」に落ちないようにしています。

### 📊 記録タブの金額

期間（今週／1ヶ月／全期間）ごとに、合計と**用途別の金額**が出ます。
用途タグはもともと買い物メモに付けているものなので、
**🍺 娯楽にいくら使ったかは何も足さずに出ます**（これが元々の目的でした）。
あわせて「前より動いたもの」を差額の大きい順に並べます。

値段を入れるときに用途が決まっていなかったもの（レシートから足した品など）は、
あとで「用途がまだのもの」で決めれば、さかのぼって内訳に入ります。

### 📷 レシートの写真から読み取る

設定で Claude の API キーを入れると、レシートを撮るだけで品名と値段が埋まります。

- 画像は端末内で長辺1600pxに縮めてから送ります
- 買い物リストの品名を一緒に渡し、`ﾌﾞﾀｺﾏ切落シ → 豚こま` の**照合まで Claude にやらせます**
  （日本語の略称マッチをコードで書くより確実です）
- 読み取り結果は**そのまま確定せず、必ず人が直せる欄に流し込みます**。
  リストになかった品は下に足されるので、消すのも値段を直すのも1タップです
- 小計・税・ポイント行は除外し、値引き行はその品から引いた額にするよう指示しています

**APIキーの置きかた。** キーは `localStorage` の別キー（`kondate.ai`）に置き、
**同期する本体にも書き出しJSONにも一切含めません**（共有のGitHubトークンと同じ扱い）。
ただしブラウザに置く以上、端末を他人に触られれば読めます。
**専用ワークスペース＋上限金額を設定したキー**を使ってください。1枚あたり数円です。

### 1人前の材料費

レシピ画面に「材料費のめやす」が出ます。直近の値段を材料1つにつき1個ぶんとして足し、
設定の人数で割ったものです。

分量を持たない方針なので正確な原価にはなりません（実際は使い切らないのでこれより安い）。
それでも**料理どうしを比べる**には十分で、「この主菜は高い」が見えます。

## 常備品のサイクル推定

- 残日数 = 目安サイクル − 最後に買ってからの日数
- 残り2日以下、または切れている → 買い物リストに自動掲載
- 買い物タブの「買い物おわり」→ チェックした常備品の購入日を今日にし、
  前回からの実際の間隔で `サイクル = 旧×0.5 + 実績×0.5` と補正
- 「まだある」→ サイクルを1.12倍し、`サイクル×0.3` 日ぶん先送り
- 「次買う」→ まだ残っているが、**次の買い物リストに載せる**。購入日もサイクルも触らない。
  「切らしてる」と違い、画面では橙の「次買う」と出る（赤の「切らしてる」ほど急ぎではないので）。
  すでにリストに載っているもの（「切らしてる」を含む）には何も起きず、弱められもしない
- 常備品タブに「買った」ボタンはありません。買い物リストに無かったものを買ったときは、
  行をタップして「最後に買った日」を直します
- 購入日が未設定のものは推定できないため、リストには載せず「最初に設定するもの」に表示。
  棚を見て「今ある」／「切らしてる」を押した時点から推定が始まります

初期プリセットとして食品・日用品・ベビー用品あわせて39品目を同梱しています。

## 初期データ

初回起動時のみ、次を入れます。不要なものは削除してください。

- **主菜12品**
  - 月（ローテーション）… ししゃも / 赤魚の煮付け / ホッケの塩焼き
  - 金（定番）… チキントマト煮 / ビーフストロガノフ / 無水チキンカレー
  - 火〜木（気分）… 麻婆春雨 / 豚の生姜焼き（肉）、鮭のホイル焼き / さばの味噌煮（魚）、厚揚げと野菜のみそ炒め / トマトと卵の炒め物（その他）
- **副菜20品** — おひたし・冷奴・味噌汁・きんぴら 等
- **常備品39品** — 食品・日用品・ベビー用品

どれも食材入りなので、承認するとすぐ買い物リストが埋まります。

**気分の主菜を最初から6品入れているのは、初めて使う人が詰まらないためです。** 以前は火〜木に
出せる主菜が1品だけで、同じ料理を連日出さないために**水曜が毎週必ず空いていました**。
肉・魚・その他を2品ずつにしています。月曜が祝日で月曜の魚が出ない週でも、
「週に魚を最低1回」で火〜木に魚が入ります。魚を1品だけにすると、月＝魚・金＝肉の並びから
水・木にその1品が30週中24週入ったため、2品にしました（2品で各料理が30週中10〜17週）。

初期データはレシピがまだ無い端末にだけ入ります。すでに使っている端末のデータは変わりません。

## 共有（2台で同じデータを見る）

サーバーは持たず、GitHubの**非公開Gist 1ファイル**を共有の置き場所にしています。
平日に「シャンプー切らしてる」を入れる、土日に献立を承認する、片方だけが買い物に行く —
このどれもが、どちらの端末からでもできます。

**設定は2手です。**

1. [トークンを発行](https://github.com/settings/tokens/new?scopes=gist&description=kondate)（scope は `gist` のみ）して、設定 → 共有 に貼り、「共有をはじめる」
2. 「ペア設定をコピー」した文字列を、もう1台の「参加する」に貼る

同期のタイミングは、起動時・アプリに戻ったとき・変更の3秒後・開いている間は1分ごと。
ヘッダーの ☁️ で状態が分かり、タップで即時同期します。

### 3方向マージ

一番怖いのは、**平日に奥さんが入れた「切らしてる」を、数日前の画面を開いたままの端末が
上書きして消してしまう**ことです。単純な「最後に書いた方が勝つ」だとこれが起きます。

前回同期した時点のスナップショット（base）を残しておき、**base / 自分 / 相手**の3つを比べます。

| 状況 | 採用するもの |
|---|---|
| 自分が触っていない | 相手の変更 |
| 相手が触っていない | 自分の変更 |
| 両方が別々に変更した | 相手（相手の変更を消さない） |

レシピ・常備品・余り食材・買い足しメモは id 単位で突き合わせるので、
**両方の追加が残り、片方の削除はきちんと伝わります**（base があるので tombstone は不要）。
2端末の実機シナリオ（参加・追記・古い画面からの上書き・削除の伝播・同時編集・トークン失効）で
検証済みです。

裏で同期が走ってもじゃまにならないよう、シートを開いている間と入力欄に書きかけがある間は
同期を見送り、表示中の週も動かしません。

**ローテーションの手動の指定（`manual`）だけは、項目ごとに混ぜず、ひとまとまりで比べます。**
片方の「料理」ともう片方の「週」を組み合わせると、どちらも指定していない状態になるためです。
両方が変えていたら相手のものをまるごと採ります。指定は料理の id で持っているので、
一方が「次はC」、他方が順番を [C, A, B] に並べ替えても、Cが出ます。

### 注意

- 「ペア設定」の文字列には**トークンが入っています**。送り先に気をつけてください
- トークンは `gist` スコープのみ。他のリポジトリには触れません
- トークンとスナップショットは共有データとは別の localStorage キーに置いているため、
  **Gistには書き込まれません**（テストで確認済み）

## データの扱い

- 保存先は端末のブラウザ内（`localStorage`）。共有をつながないかぎり外部への通信はありません
- 共有をつなぐと、同じ内容がGitHubの非公開Gistにも保存されます（実測 約18KB）
- 設定画面から JSON で書き出し／読み込みができます
- 古い週と値段の記録は400日で自動的に間引かれます
- レシート読み取りのAPIキーだけは別キー（`kondate.ai`）に置き、同期・書き出しには含みません
- `noindex,nofollow` を指定しています
- 公開版は別のホスト名・別のキー（`osakana.v1`）なので、家庭用のデータとは混ざりません（下の「公開版」）

## 仕様として決めたこと：2週以上先の週を先に作ったとき

ローテーションは「その週より前の週に、この曜日で最後に出た料理の次」を出します。
そのため、2週以上先の週を先に作ると、間の週は空のまま順番が決まります。
あとから間の週を作っても、**先に作った週は自動では変えません。**

**この挙動のままにしています。** 理由は、一度見せた献立（買い物リストを作ったかもしれない週）を
裏で書き換えるほうが困るからです。先の週を先に作るのは、旅行の前などのまれな使い方です。

ただし、この使い方では間の週と先の週で同じ料理が続くことがあります
（例：A→B→C で、12/7 が A のときに 12/21 を先に作ると B。あとで 12/14 を作るとこれも B）。
気になるようなら、間の週を作るときに**次の週のその曜日に入っている料理を避ける**
（12/14 は C にする）小さな手当てを入れられます。先に作った週は変えません。

## ホーム画面のアプリが古いままになる問題

ホーム画面に追加したアプリは、iOS が前回の画面を**メモリに残したまま再開**します。
そのためページを直して公開しても、**開き直しただけでは古い画面で動き続けます**
（配信元の GitHub Pages のキャッシュも最大10分あります）。

そこで、アプリ自身が新しい版を確かめます。

- 起動時と、アプリに戻ってきたときに、自分自身を `cache: 'no-store'` で取り直す
- 中の `BUILD`（版の目印）が違えば `?v=<新しい版>` を付けたURLに切り替える
  （新しいURLなのでHTTPキャッシュに当たらない。**データは localStorage にあるので消えない**）
- **入力中・画面（シート）を開いている最中は勝手に切り替えず**、下に「🔄 新しい版があります［更新］」を出す
- 同じ版への自動切り替えは1回だけ（配信の反映待ちなどで無限に読み直さないため）
- 通信できないときは黙って何もしない（オフラインでも普通に使える）
- 効かないときは ⚙️ 設定 →「🔄 最新版を確認して更新」で手動確認。いま見ている版もそこに出る

**この仕組みを入れる前の版には、この確認がありません。** 一度だけ、アプリを完全に終了
（アプリ切り替え画面で上にスワイプ）してから開き直してください。まだ古ければ10分ほど置いて
もう一度。この版が一度読み込まれれば、以後は自動で追従します。

> ⚠️ iOS では **Safari のタブとホーム画面のアプリでデータが別々**です（localStorage を共有しません）。

## 公開版（X・Threads で配る版）

家庭用と**同じ `index.html`** を別のホスト名に置き、開いたホスト名で動きを切り替えます。

| | 家庭用 | 公開版 |
|---|---|---|
| URL | https://spicy-device.com/kondate/ | https://osakana.spicy-device.com/ |
| 保存 | localStorage `kondate.v1` | localStorage `osakana.v1`（ホスト名も別なので混ざらない） |
| 最初の画面 | いつもの献立 | 「5日分の献立を見る」ボタンだけ |
| Gist の共有 | あり | **なし**（ペア設定の文字列に GitHub のトークンが入る。Gist の「非公開」は URL を知っていれば誰でも見られる） |
| レシート・売り場の写真読み取り | あり | **なし**（Claude の API キーを入れさせない） |
| 家族と共有 | Gist | 「📋 コピー」→ LINE などに貼る |
| 計測 | なし | 5段階の回数だけ |

`?public=1` を付けると、家庭用の場所でも公開版の画面を試せます（保存のキーが別なので、家庭用のデータには触りません。計測は送りません）。

### 最初の体験

1. 開くと「**5日分の献立を見る**」だけ。曜日の設定もレシピの登録も求めません
2. 押すと、その場で**次の月曜から**の5日分が出ます（土日に開いたときは翌日の月曜から）
3. 献立の下の「**この献立で買い物リストを見る**」で、承認と買い物タブへの移動を1タップで
4. 初回は「このブラウザに自動保存されます」と短く出します

平日に作った人が開き直したときは、空の今週ではなく、作った来週の献立を見せます。

### アプリ内ブラウザ

X・Threads のアプリの中のブラウザやプライベートブラウズでは、保存が消えることがあります。
アプリ内ブラウザ（Threads・Instagram・Facebook・LINE・Android の X）を見分けたとき、または
X・Threads 用のリンクからスマホで来たとき（iOS の X は見分けられないため）に、
「リンクをコピー」と「いつものブラウザで開く」案内を出します（✕ で閉じられる）。
コピーしたリンクには `ext=1` が付き、開いた先では案内を出しません。

保存に失敗したら「保存できませんでした。いつものブラウザで開いてください」と出し、計測にも残します。

### 計測（5段階だけ）

Plausible の**イベント API に直接送ります**（外部スクリプトは読み込みません。Cookie も使いません）。
送るのは決まったイベント名と、流入元つきのページURLだけです。**献立名・食材名・入力内容は送りません。**
設定画面の「計測について」に、何を数えているかを書いています。

| イベント名 | 記録する時点 |
|---|---|
| `first_view` | 初めて開いた |
| `plan_shown` | 献立ができて表示された（主菜が1日以上入った） |
| `plan_confirmed` | 承認できた（1日以上） |
| `list_shown` | 中身のある買い物リストを表示した |
| `first_check` | 買い物リストに初めてチェックを付けた |
| `plan_incomplete` | 献立に主菜の無い日が残った（献立が一部未定） |
| `save_failed` | 保存に失敗した |

- ボタンを押した回数ではなく、**処理ができた時点**で記録します
- `save_failed` 以外は**その端末で1回だけ**数えます（何人がその段階まで来たかを見るため）
- 流入元は、最初に来たリンクの `utm_source` で決めて、以後もその値を付けて送ります

**流入元ごとのリンク**（投稿にはこれを貼る）

- X … `https://osakana.spicy-device.com/?utm_source=x`
- Threads … `https://osakana.spicy-device.com/?utm_source=threads`

### 困ったところを送る

公開版の設定と、献立・買い物タブの下に出ます。「献立が決まらない／買い物リストが空／保存されない／その他」
から選んで送るだけで、補足の入力は任意です。計測で「どこで止まったか」を見て、ここで「なぜ止まったか」を拾います。
送り先は Google フォームで、どこまで進んだか（例 `plan_shown / x`）も一緒に送ります。

### 公開までの準備（一度だけ）

`index.html` の `PUB_CFG` を埋めます。空のあいだは、計測は送らず、「困ったところを送る」も出しません。

1. **Plausible** … サイト `osakana.spicy-device.com` を登録し、上の7つをカスタムイベントのゴールに登録。
   `PUB_CFG.plausibleDomain` に `'osakana.spicy-device.com'` を入れる。
   流入元は Sources（utm_source）で、段階は各ゴールの訪問者数で見る
2. **Google フォーム** … 質問を3つ作る：
   「どこで困りましたか」（ラジオボタン：献立が決まらない／買い物リストが空／保存されない／その他）、
   「補足（任意）」（段落）、「どこまで進んだか（自動）」（記述式）。
   「事前入力した URL を取得」で各項目の `entry.xxxxxxxx` を調べ、`PUB_CFG.formAction`
   （`https://docs.google.com/forms/d/e/<フォームのID>/formResponse`）と `formChoice` / `formNote` / `formStage` に入れる
3. **公開用のリポジトリ** … GitHub Pages を有効にし、カスタムドメインを `osakana.spicy-device.com` に
4. **DNS** … `osakana` の CNAME を `t-fujiya-sd.github.io` に向ける
5. **写す** … `sh kondate/stamp.sh` → portfolio 側を commit → `sh kondate/publish-public.sh <公開用リポジトリのフォルダ>`
   → 写した先で確かめて commit・push

家庭用を直したときも、公開版へは手順5で同じファイルを写します（ファイルは1つなので、直すのも1か所）。

## 構成

単一HTML（外部依存なし・オフライン動作）。

```
kondate/
  index.html          アプリ本体（家庭用と公開版で同じファイル）
  stamp.sh            公開前に版の目印（BUILD）を更新する
  publish-public.sh   公開版のリポジトリへ index.html とアイコンを写す
  README.md           このファイル
```

ホーム画面に追加するとフルスクリーンで起動します（`apple-mobile-web-app-capable`）。
