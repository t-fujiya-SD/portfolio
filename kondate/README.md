# コンダテ — 平日5日の献立・買い物・常備品

平日だけ自炊する家庭のための、**献立 → 買い物リスト → 常備品** を一直線につないだ単一HTMLアプリ。
日曜日にまとめ買いする運用を前提にしています。

```
定番レシピ（プール）
   ↓ 平日5日ぶんを自動提案 / 手動で差し替え
今週の献立
   ↓ 食材を自動で集約
買い物リスト ← そろそろ切れる常備品が自動で合流
   ↓ 買ったらチェック
常備品の「最後に買った日」が更新され、サイクルを学習
```

## 解いている課題

| 面倒 | 仕掛け |
|---|---|
| 毎週の献立を決めるのがしんどい | 登録済みの定番からルールに沿って1週間ぶんを自動提案。気に入らない日だけ🎲で引き直す |
| 決めたあと必要な食材を覚えていられない | 献立を決めた時点で買い物リストが完成している。各食材に「何曜日の何に使うか」が付く |
| 常備品の在庫と買い忘れ | 在庫を数えない。「買った日＋目安サイクル」から切れる時期を推定し、リストに自動で載せる |

## 設計上の判断

**分量は管理しない。** レシピの分量（玉ねぎ 1/2個）と店で買う単位（3個入りネット）が違うため、
足し算しても結局その場で人が判断することになります。代わりに **「何曜日の何に使うか」** を出します。
「2品で使う＝多めに」は見れば分かりますし、「カレーか、ならルーもいるな」と気づけます。
分量入力が不要になるぶん、レシピ登録が1品20秒で済むという副次効果のほうが大きい。

**在庫は数えない。** 「卵を1個使った」を毎回記録する運用は続きません。
記録するのは「買った」の1回だけ。実際に見て残っていたら「まだある」を1タップ。
そのズレからサイクルを自動補正するので、初期値が雑でも1ヶ月で実態に寄ります。

**「今日は作らない」を最初から入れる。** 平日5日が必ず自炊とは限りません（外食・残り物）。
外食にした日の食材は買い物リストから消えます。

**「作った」ボタンを押させない。** 献立に入れた時点で作った扱いにし、作らなかった日だけ後から外す。
逆にすると記録が続きません。

## 献立の自動提案ルール

- 同じタンパク源（肉／魚／その他）を2日連続にしない
- 週に魚を最低1回
- 傷みやすいもの（魚→肉→その他）を週の前半に配置。日曜まとめ買いでは効きます
- 最近作ったものは出さない（間隔が空くほど高スコア）
- 「余っている食材」に登録したものを使うレシピを優先
- 金曜は時短（所要時間の短いもの）を優先
- 魚の固定枠（初期値：月曜）

空きスロットへの並べ方を全通り（最大 5! = 120通り）試し、スコアが最大の配置を採用します。

> **ルールが両立しないケース**：肉料理が週3品あると、2日連続を避けるには肉が月・水・金に固定されるため、
> 魚を月曜に置けません。この場合は **ユーザーが明示的に設定した固定枠を優先**し、
> 連続1回ぶんまでを妥協します（2回以上の連続は許容しません）。
> 固定枠を「なし」にすれば連続はゼロになり、傷みやすさのルールで魚は週の前半に入ります。

## レシピの取り込み（貼り付けパーサー）

レシピサイトの材料欄や YouTube の概要欄をコピーして貼るだけで、食材だけを抽出します。

- `材料` `【材料】` を検出し、`作り方` `手順` `http` などが現れるまでを材料ブロックとして切り出す
- 箇条書き記号（`・` `-` `■` `①`）、区切り（`…` `：` タブ）、分量（`200g` `1/2個` `大さじ2` `適量`）を除去
- 常備調味料（醤油・みりん・ごま油・豆板醤・鶏がらスープ…）は自動で除外
- 残った食材を売り場カテゴリ（野菜／肉／魚／豆腐卵乳／乾物麺／調味料／冷凍／日用品）に自動仕分け
- 魚が含まれれば「魚」、肉なら「肉」とタンパク源タグを自動判定
- 料理名と所要時間（`15分`）も推測
- 最後に確認画面。カテゴリは絵文字タップで変更、不要なものは `✕` で削除

クックパッド系（タブ区切り）、YouTube概要欄（`・食材…分量`）、`名前：分量` 形式、食材の羅列のみ、で動作確認済み。

> URLだけを貼っても取り込めません。ブラウザから他サイトの中身を直接読めない（CORS）ためです。
> ページを開いて材料欄をコピーしてください。

## 買い物リスト

スーパーの売り場順（野菜 → 肉 → 魚 → 豆腐卵乳 → 乾物麺 → 調味料 → 冷凍 → 日用品）に並びます。
献立の食材と常備品が同名の場合は1行にまとめます。
「📋 コピー」で献立＋未購入リストをテキスト化できるので、LINE等で共有できます。

## 常備品のサイクル推定

- 残日数 = 目安サイクル − 最後に買ってからの日数
- 残り2日以下、または切れている → 買い物リストに自動掲載
- 「買った」→ 前回からの実際の間隔で `サイクル = 旧×0.5 + 実績×0.5` と補正
- 「まだある」→ サイクルを1.12倍し、`サイクル×0.3` 日ぶん先送り
- 購入日が未設定のものは推定できないため、リストには載せず「最初に設定するもの」に表示。
  棚を見て「今ある」／「切らしてる」を押した時点から推定が始まります

初期プリセットとして食品・日用品・ベビー用品あわせて39品目を同梱しています。

## データの扱い

- 保存先は端末のブラウザ内（`localStorage`）のみ。外部への通信は一切ありません
- 設定画面から JSON で書き出し／読み込みができます（端末の移行用）
- `noindex,nofollow` を指定しています

**現状は端末ごとにデータが分かれます。** 2人で同じリストをリアルタイムに見るには、
バックエンド（Google スプレッドシート＋GAS など）を足す必要があります。
まずはこの形で日曜の運用が回ることを確かめてから、共有基盤を足す想定です。
