# 事業導線の設計：ポジショニング → 証拠 → 会話

最終更新: 2026-09-22 / ステータス: 設計（未実装）/ 版: v2（v1を破棄して再構成）

---

## 0. 結論

**やるべきことは「ブログとツールで集客する」ではなく、「何屋かを1つに決めて、証拠を置く」です。**

順序はこう。

```
① ポジショニングを1つに決める      ← 今できていない。ここが全部の前提
② 証拠（数字入りの事例）を置く      ← 最優先。記事10本よりこれ1本
③ 検索の受け皿を3本だけ作る        ← サイト記事
④ 絞り込むツールとフォームを置く    ← ゲートは「集める」ではなく「絞る」装置
⑤ 書き続けられる1チャネルだけ回す   ← note。Instagram/X/LinkedInは当面やらない
```

### 前回設計（v1）から変えた点と、その理由

| v1 | v2 | 理由 |
|---|---|---|
| 記事→ツール→メール取得→ナーチャリング | 証拠→名指しの1件→会話 | **顧客数N=3の商売にリード量産のファネルは過剰**。必要なのは年1〜3社 |
| ゲートは摩擦を減らして取得数を最大化 | ゲートは**あえて摩擦を足して絞る** | メアド10件より「3店舗で店舗間精算が手作業」という名指し1件 |
| 出店シミュ／銀行計画表を主力の無料ツールに | **FC・卸向けの武器に用途変更** | 開業前の個人は単発・低予算・開業後にチャーン。顧客プロファイルと合わない |
| 4課題×4記事×4ツール | **1ポジション×事例3本×記事3本** | 4課題に散らすと「何屋か」が伝わらない。現状の問題がまさにそれ |
| Instagram を優先度2位 | **当面やらない**（優先度5位） | 買い手（卸の経営者・多店舗の役員）はInstagramで business を探していない |
| LinkedIn は「日本の飲食業界にいない」ので保留 | **優先度4位に格上げ** | 個人飲食店オーナーはいない。ただし**食品卸・商社の食品部門・チェーン本部の管理層はいる** |
| noteは切ってよい | **noteは切らない。唯一回すチャネル** | 最も安く続き、既に声が出来ている（直近6本が全部オンテーマ）。失敗したのは頻度で、媒体ではない |

## 1. ポジショニング

### 1-1. 今の問題は「デモが多いこと」ではない

本人の認識は「効率化デモをたくさん載せているスタイルを変えたい」。
実際の問題はデモの数ではなく、**15本が別々の方向を向いていて「この人は何屋か」に答えがないこと**。
「何でも作ります」は買い手には commodity に見え、価格でしか比較されない。

### 1-2. ところがデモは、実はきれいに1つに集まっている（確信度: 高）

| デモ | 中身 |
|---|---|
| ハシリ板 | 「市場・倉庫・車上・事務所で**同時刻に一緒にいない人たち**の間で」の申し送り |
| 店舗間フードリレー | 店舗間の食材の貸借 → 月末に精算 |
| 店舗間ヘルプ | 店舗間の応援 → 人件費の貸借を精算 |
| TOYO LINK | 豊洲の卸間で在庫の余り／不足をマッチング |
| 仕入れ見える化レポート | 卸 → 飲食店へ仕入れをレポート |
| デシャップボード | 多店舗の連絡を1か所に |

**7本が「同じ場所にいない人・会社の間の、モノ・カネ・情報の受け渡しと精算」。**

3クライアントも同じ構造をしている。

| クライアント | 立ち位置 | 委託業務の構造 |
|---|---|---|
| 旬彩坊（野菜仲卸） | 売り手側 | 新規営業・売上導線・業務効率化・FC加盟店の開業/運営支援 |
| ジャパンダイニング（銀座楼蘭） | 買い手側 | 総合コンサル（集客・コスト改善・会議運営・戦略立案） |
| VRtrade（デリバリー食材仲介） | プラットフォーム側 | 加盟店アカウント発行・商品登録・価格変更・月末締め・エラー特定・データ管理 |

**食品流通の売り手・買い手・プラットフォームの3side全部に同時に入っている。** これは極めて珍しい。
卸のマージン構造と、飲食店の原価圧力と、プラットフォームのデータフローを同時に見ている人はほぼいない。

note の直近6本も同じ方向に寄っている（4本が仕入れ・購買）。
`/other/` ページには既に「飲食店だけでなく、卸・小売・食品メーカーなど『食』に関わる現場」と書いてある。
**本人が既に気づいている。サイト構造がそれに追いついていないだけ。**

### 1-3. 採るべきポジション

> **飲食・食品流通の「あいだ」を整える人**
> — 店舗と店舗のあいだ／卸と店のあいだ／市場と事務所のあいだ／プラットフォームと加盟店のあいだ。
> 同じ場所にいない人たちの受け渡しと精算を、記録できて精算できる形にする。しかも助言ではなく、手を動かす。

候補と比べて、なぜこれが最善か。

| 候補 | 競合 | 判定 |
|---|---|---|
| 飲食店の数字を整える | 会計事務所・POSベンダー・コンサル多数 | 埋もれる |
| 飲食店向けWebツール制作 | 制作会社多数。価格競争 | commodity |
| 飲食業界のDX・データ屋 | SIer・SaaS。抽象的 | 差別化が弱い |
| **「あいだ」を整える** | **ほぼ無競合** | **採用** |

決定的な利点は**紹介しやすさ**。
「店舗間の精算やってくれる人がいるよ」は口頭で伝わる。「飲食店のDXやってる人」は伝わらない。
この商売は紹介が1位なので、**紹介の際に一言で言えるかどうか**が最重要要件になる。

### 1-4. 「外注として手を動かす」を併記する

「外注業者として、業務の中に入り込んでいる」は助言型コンサルに対する明確な差別化。
VRtradeの月末締め・エラー特定まで自分でやっている事実は、これを裏づける最強の材料。
**「助言はしません。締め作業までやります」**は短くて強い。

## 2. 顧客数 N=3 の商売である、という前提（v1最大の誤り）

クライアントは3社。次の契約はN=4。必要なのは**年1〜3社**で、100リードではない。

これが設計を根本的に変える。

| | 量のビジネス | **N=3のビジネス（こちら）** |
|---|---|---|
| ゴール | リード数 | **名指しの相談を月1件** |
| ゲート | 摩擦を減らして最大数を取る | **摩擦を足して絞る** |
| フォーム項目 | 少なく（メアドだけ） | **多く**（社名・役職・拠点数・困りごと） |
| 取得後 | ステップ配信で温める | **自分が個別に返す**（月数件なら可能） |
| コンテンツ | 量を増やして裾野を広げる | **証拠を深くする** |
| KPI | PV・フォロワー・CVR | **名指し相談数・紹介発生数・事例本数** |

**PVとフォロワー数は、この規模では意思決定に使えません。** 確信度: 高。
追い始めた瞬間に工数が溶ける。

## 3. 最優先は「証拠」：数字入りの事例（サイト改修よりも、SNSよりも先）

買い手の判断は **「自分と似た会社で、実際に効いたのか」** だけで決まる。
記事10本より、数字の入った事例1本が効く。紹介も事例があって初めて成立する。

### 3-1. 作る事例（3系統 × 1本）

| 系統 | 元クライアント | 書くべき数字の例 |
|---|---|---|
| 卸・仲卸 | 旬彩坊 | 新規営業の導線本数／受発注にかかる時間／FC加盟店の立ち上げ期間 |
| 多店舗飲食 | ジャパンダイニング | 原価率の変化／会議時間／レポート作成時間 |
| 流通プラットフォーム | VRtrade | 月末締めの所要時間／エラー発生件数と特定までの時間／登録商品数 |

### 3-2. 守秘の制約と、その回避

**各社の許可取りが前提。** 取れない場合の段階的な逃げ道：

1. 実名＋数字（最強。許可が必要）
2. 業種＋規模＋数字（「野菜仲卸A社・従業員15名／月末締めを◯時間削減」）← **現実的にここを狙う**
3. 数字なしの業務記述（弱い。最後の手段）

許可が取れた順に公開する。3本揃うのを待たない。**1本目が出た時点でサイトの説得力が変わる。**

### 3-3. これがSNSより先である理由

事例がないままSNSを回すと、興味を持った人が来ても判断材料がなく、何も起きない。
順序を逆にすると工数が丸ごと無駄になる（確信度: 高）。

## 4. チャネル設計（要約）

> **詳細は `docs/channel-map.md`** — 全導線・媒体の目的／ゴール／役割、各SNSの判定根拠、
> 運用仕様、最初の30日、撤退基準。以下はその要約。

### 4-1. 5段階モデル

```
⑤ 続ける ──→ ① 出会う（紹介） ──→ ② 確かめる ──→ ③ 判断する ──→ ④ 話す ──→ ⑤
     └──────────────── これがこの商売のエンジン ────────────────┘
```

世の中のチャネル設計はほぼ①（認知）向けに作られている。
**この商売のボトルネックは②（確かめる）**で、そこが空だと①をいくら増やしても止まる。

### 4-2. いま最大の穴は「確かめる材料」がないこと（確信度: 高）

| 確かめる材料 | 現状 |
|---|---|
| 指名検索での実在性 | **不足**。JSON-LDに `sameAs` `logo` が無い |
| サイトの事例（数字入り） | **0本** |
| 会社案内PDF | **事例なし**。「公開中の制作デモ」になっている |
| SNSアカウントへのリンク | **LINEとnote以外は1つもない** |

**投稿を始める前にここを埋めるのが先。**

### 4-3. 買い手はどこにいるか

買い手は**卸・仲卸の経営者／多店舗飲食企業の役員／流通プラットフォームの運営者**。
いずれも個人飲食店オーナーではない。

| 場所 | 濃さ |
|---|---|
| 同業のネットワーク（市場・組合・仕入れ先・取引先） | 圧倒的1位。卸業界は横の繋がりが極端に濃い |
| **指名検索**（社名・氏名） | 紹介の裏取りに必ず使われる。最優先 |
| 課題検索 | 極少量・超高確度 |
| LinkedIn | 少量・高signal（食品卸・商社・チェーン本部の管理層） |
| Facebook | 50代前後の経営者層が残っている（確信度: 中） |
| note | 買い手は読まないが、人柄の裏取りに使われる＋Googleに乗る |
| Threads | 幅広い。フォロワー外に配られるので初速が出る |
| Instagram / X / TikTok | 買い手が薄い |

### 4-4. 判定一覧

| 判定 | 媒体 | 月工数 |
|---|---|---|
| **最優先** | 事例ページ、指名検索の整備（構造化データ＋第三者言及） | 初期8h |
| **やる** | 既存クライアント経由の紹介、自社サイト、note（母艦・月1本） | 5〜8h |
| **転記のみ** | Threads（週2〜3）、LinkedIn（月1） | 1〜1.5h |
| **置くだけ** | Facebook（個人）、Instagram（投稿しない） | 0.6h |
| **営業資料として** | YouTube（ツール操作動画2〜3本。集客はしない） | 単発 |
| **やらない** | X（読む側専用）、TikTok | 0 |
| **狙う価値が高い** | 登壇・勉強会（1回で記事100本ぶん） | 変動 |

**「Instagram / X / LinkedIn / Threads を同時に立ち上げる」が最悪の選択。** 確信度: 高

### 4-5. v1・前回説明から変えた判定と理由

| 媒体 | 変更 | 理由 |
|---|---|---|
| **Threads** | 新規に採用（転記） | Instagramと同じ層を狙えて、画像制作コストがゼロ、本文にリンクが貼れ、フォロワー外に配られる。**Instagramより1桁安い** |
| **Facebook** | 新規に追加（置くだけ） | 前回の漏れ。飲食・卸業界の経営者は50代前後が多く、この層はFacebookにいる。買い手に対してはLinkedInより濃い可能性がある（確信度: 中） |
| **Googleビジネスプロフィール** | 一度推奨 → **撤回** | **シェアオフィスは同一住所に複数事業者が並ぶためGBP規約上リスクが高く、来店型でもないので地図枠に価値がない。** 目的（指名検索での実在性）は正しいので、手段を構造化データの `sameAs`/`logo` と第三者言及に差し替える |
| **指名検索SEO** | 新規に分離（最優先） | 前回は課題検索SEOと混ぜていた。紹介が1位なのだから、指名検索の整備が新規キーワードより先 |
| Instagram | 「やらない」→「置くだけ」 | アカウントが存在して事例へのリンクがあれば②の役目は果たす。投稿はしない |
| X | 「やらない」を維持・根拠を明確化 | 業界ニュース自動取得があっても実工数は月2〜3h。それはThreadsに回した方がリンクが効いて導線になる |
| YouTube | 「集客チャネル」→「営業資料」 | 操作説明動画は商談と加盟店説明で強い。集客としては工数が重すぎる |

### 4-6. 「noteは切り捨ててよい」への回答

**切るべきはnoteではない。切るべきは「全チャネルをやる」という発想。**

- 既に声が出来ている（直近6本が全部オンテーマ、うち4本が仕入れ・購買）
- 最も安い。書くこと以外のコストがゼロ
- 自社ドメインが育つまでの数年、noteのドメインを借りられる
- 失敗の原因は媒体ではなく**頻度**（2026-04-24から5ヶ月停止／確信度: 高）

やめるべきなのは、noteを「集客チャネル」と期待すること。
**noteは裏取りと人柄の置き場**と位置づければ、月1本で役目を果たす。

### 4-7. 期待値の設定（正直に）

**SNSを3つ回しても、この規模では契約は直接生まれない。** 確信度: 高
SNSの役割は「確かめたときに生きていると分かる」ことと「紹介の摩擦を下げる」こと。
契約を生むのは紹介と指名検索。ここを取り違えると、必ず「効果がない」と判断して止めることになる。

## 5. note と 自社サイト の使い分け（当初の質問への回答）

### 5-1. 判定テスト

v1では「そのタイトルで検索する人がいるか」で分けた。v2ではより本質的な問いに変える。

> **それは「買う判断」に使われるか、「人を知る」ために使われるか。**

- 買う判断に使われる → **サイト**（事例・料金・進め方・ツール・検索記事）
- 人を知るために使われる → **note**（考え方・現場・失敗談・業界への意見）

紹介された人は、まず**サイトで事例を見て判断し、noteで人柄を確かめる**。
この2段階が、そのまま2媒体の役割分担になる。

### 5-2. 役割の対比

| | 自社サイト | note |
|---|---|---|
| 読者 | 買う直前の人／紹介された人／検索して来た人 | 人柄を確かめに来た人／回遊中の人 |
| 置くもの | 事例（数字）・サービス・料金・ツール・検索記事 | 考え方・現場の話・業界への意見 |
| 型 | ストック。更新して育てる | フロー。書きたいことを書く |
| 本数 | **記事は3本だけ** | 月1本 |
| 文量 | 2000〜4000字 | 800〜1500字 |
| CTA | 相談フォーム（絞り込み型）へ1つ | 事例かサイト記事へ1本だけ。売り込まない |
| 資産性 | 自分のもの | noteのもの（消えても既存9本は痛くない） |
| 計測 | GoatCounter＋自前イベント | note管理画面（粗い。気にしない） |

### 5-3. 既存note記事は移植しない（v1の訂正）

v1では「既存note記事4本をサイトに移植するのが一番早い」と書いた。**これは誤り。**

- 6本すべてが「気づき・意見型」で、検索型が1本もない（「仕入れ先 変えると怒られる」で検索する人はいない）
- 移植しても検索流入は増えず、note側の既存順位とカニバる

**やる価値があるのは1回だけの作業**：note のプロフィール欄と既存9本の記事末に、
事例ページへのリンクを追記する。一度で済み、効果が高い。

### 5-4. サイト記事は3本だけ（買い手のキーワードで）

「あいだ」ポジションから素直に落ちるキーワードだけを狙う。

| 記事 | 狙うキーワード | 関連する証拠 |
|---|---|---|
| 店舗間の食材・人の貸し借りを、精算できる形にする | 店舗間 精算／多店舗 ヘルプ 人件費／店舗間 食材 貸し借り | food-relay, help-settle |
| 卸の受発注と申し送りを、記録できる形にする | 卸 受発注 効率化／仕入れ 見える化／卸 申し送り | hashiri-ban, toyosu-relay, procurement-report |
| 仕入れを見直したのに利益が残らない理由と、確かめ方 | 飲食店 原価率 下げる／仕入れ 見直し 効果測定 | procurement-report |

検索ボリュームは小さい。**それでいい。** このキーワードで検索する人は課題が言語化済みで、
月1件でも来れば十分に成立する（確信度: 中／実際のボリュームは未検証）。

### 5-5. 1コンテンツの流し方

```
note記事（月1本・書きたいことを書く）
  ├→ 要約して LinkedIn に転記（0.5h）
  └→ 記事末 → 事例ページ or サイト記事 へ1本だけ

サイト記事（四半期1本・計3本で完成）
  └→ 記事末 → ツール → 絞り込みフォーム → 自分が個別に返す

事例（四半期1本・許可が取れた順）
  └→ トップ最上段に置く。紹介時にURLを渡す
```

## 6. サイト構造

トップが答えるべき問いを1つに絞る：**「そのやり取り、まだ手作業でやっていませんか」**

```
/                 ヒーロー：「あいだ」の問い（一つだけ）
                  ├ 事例（数字入り・3件）      ← 最上段。これが主役
                  ├ 何をやるか（3つに絞る）
                  ├ 使えるツール（あいだ系3本）
                  ├ 進め方・料金（既存 #flow #pricing を流用）
                  └ 相談（絞り込み型フォーム）

/works/           事例詳細（卸／多店舗／プラットフォームの3系統）
/tools/           ツール一覧（あいだ系を前面、単店向けは下）
/blog/            上段=サイト記事3本 ／ 下段=noteコラム
/other/           既存の「卸・小売・食品メーカー向け」← 実質これが主役に近い
```

### 6-1. `/other/` を昇格させる

`/other/` には既に「飲食店だけでなく、卸・小売・食品メーカーなど『食』に関わる現場」と書いてある。

## 7. ツールの位置づけ（v1から用途変更）

### 7-1. ゲートは「集める装置」ではなく「絞る装置」

N=3の前提から、ゲートの目的を反転させる。

- ツールを触る・計算する・画面で結果を見る → **完全無料・登録不要**
- Excel/PDF出力・保存 → **フォーム。ただし項目を多く取る**

| 取る項目 | 理由 |
|---|---|
| 会社名・店舗名（必須） | 誰かが分からない相談は追えない |
| 役職（必須） | 決裁者かどうかで対応が変わる |
| 拠点数・店舗数（必須） | 「あいだ」の課題があるかの判定に直結 |
| 今いちばん手作業なもの（必須・選択式） | これが相談の入口になる |
| メール（必須）／LINE（任意） | 連絡手段 |
| どこで知ったか（任意・選択式） | チャネル判定に使う唯一の確実な手段 |

**取得数は減ります。それが狙いです。** メアド10件より名指しの1件。
取得後は**ステップ配信ではなく自分が個別に返す**（月数件なら可能で、転換率が段違い）。

LINEのキーワード自動応答（友だち追加を実質検証できる方式）は有効なので併用する。
ただし主経路はフォーム。LINEは既存リードへの再接触用。

### 7-2. 出店シミュレーション／銀行計画表の用途を変える

本人の当初案では、この2本がフラッグシップの無料ツールだった。**これは狙う相手がずれます。**

開業前の個人は、単発・低予算・開業後にチャーンし、月額顧問の顧客プロファイルと合わない。
この funnel を主力にすると**払えない人が集まる**（確信度: 中〜高）。

代わりに、はるかに強い用途がある。

> **旬彩坊のFC加盟店開発ツールとして。**
> 卸がFCで飲食店を増やすとき、加盟希望者に出店シミュレーションと融資用計画表を出せることは、
> 卸側の営業の武器になる。同じ構造の卸・FC本部にもそのまま売れる。

つまり**直接集客の道具ではなく、卸・FC本部に対する自分の価値を上げる道具**。
作る価値はあるが、自社サイトの入口には置かない。

### 7-3. 出力形式を見直す ― 本人がOfficeを使っていない（考慮漏れの訂正）

**藤谷さんはOfficeソフトを使っておらず、業務はGoogleのアプリで完結している。**
これは事前に共有されていた情報だが、v1・v2の設計に反映できていなかった。

現状: `/opening-simulator/` は SheetJS で `.xlsx` を出力している
（`opening-simulator/index.html:481` の `XLSX.writeFile`）。

| 問題 | 内容 |
|---|---|
| 本人が中身を確認・修正できない | Excelが手元にないので、顧客に渡す前の検算やカスタマイズができない |
| 顧客側も同様の可能性 | 中小の飲食店・卸もOfficeを持たない先が少なくない |
| 銀行提出用としては別の問題 | 提出物は最終的に紙かPDF。Excelのまま出す場面は少ない |

**修正方針（確信度: 中〜高）**

1. **PDF出力を主にする。** 銀行・公庫への提出物として体裁が完成する形
2. `.xlsx` は残す（Googleスプレッドシートで開けるので互換性の問題はない）。
   ただし「編集したい人向け」の副次的な出力に位置づけを下げる
3. **Googleスプレッドシートのテンプレを用意し、「コピーを作成」URLで共有する。**
   本人と顧客の運用にいちばん合う形で、卸・FC本部に渡す武器としても扱いやすい

`/bank-plan/` は最初からこの前提で作る。

---

既存 `/opening-simulator/` は十分に動いている（5年PL・損益分岐・投資回収・Excel 4シート出力）。
`/bank-plan/`（月次資金繰り・返済計画・公庫項目に対応した出力）は差分だけなので、
計算エンジンを共通化すれば開発量は小さい。着手はPhase 4。

## 10. リスクと未検証事項

1. **ポジションを絞ると、一部の仕事が来なくなる（確信度: 高）**
   「あいだ」に寄せると、単店のSNS集客やWebツール制作単発の依頼は減る。
   それを失っていいかは事業判断。N=3で年1〜3社なら、絞る方が有利と判断している。

2. **事例の許可が取れないと、この設計の柱が立たない（確信度: 高）**
   最悪の場合は匿名化＋数字のみに落とす。それでも取れないなら、
   自作ツールの画面と一般論だけで戦うことになり、説得力は大きく落ちる。

3. **検索ボリュームが想定より小さい可能性（確信度: 中）**
   「店舗間 精算」等は実ボリュームを検証していない。Phase 2 で実測して、
   ゼロに近ければ検索を捨てて紹介一本に絞る判断もありうる。

4. **LinkedInの食品卸セグメントの浸透率は未検証（確信度: 中）**
   工数が月0.5hなので外れても損は小さい設計にしてある。

5. **ゲートは静的サイトでは強制できない（確信度: 高）**
   JSのゲートはDevToolsで回避できる。ただしv2では目的が「絞り込み」なので、
   回避されることの損失はv1よりさらに小さい。

6. **本人が書き続けられるか（確信度: 中）**
   v2ではサイト記事3本＋note月1本まで落とし、SNSは転記のみにした。
   これでも続かない場合は、記事を捨てて事例と紹介だけに絞るのが正解。

## 11. 決定済みと、未決定

### 決定済み

| 論点 | 決定 |
|---|---|
| 最優先 | ポジショニング確定 → 事例（数字入り）1本 |
| ゲートの目的 | 取得数の最大化ではなく、絞り込み |
| 記事の置き場 | サイト＝買う判断の材料（3本）／note＝人を知る材料（月1本） |
| 既存note記事 | 移植しない。プロフィールと記事末にリンク追記のみ |
| 注力チャネル | 紹介 ＞ サイト（事例・指名検索・GBP） ＞ note（母艦） ＞ Threads・LinkedIn（転記のみ） |
| 置くだけ | Facebook（個人）、Instagram（投稿しない） |
| やらない | X（読む側専用）、TikTok。YouTubeは営業資料としてのみ |
| 最優先の3点 | 事例ページ・構造化データの整備・第三者からの言及 |
| 見送り | Googleビジネスプロフィール（シェアオフィス／非来店型のため） |
| 既存デモ | あいだ系6本を前面、単店向けは `/works/` に格下げ。URLは維持 |
| 出店シミュ／銀行計画表 | 直接集客の入口にせず、卸・FC本部向けの武器として使う |
| KPI | 名指し相談数・紹介数・事例本数。PVとフォロワーは見ない |

### 未決定（事業判断が必要）

1. **「あいだ」ポジションを採るか。** 採ると単店向けの単発依頼は減る
2. **事例公開の許可を、どの会社から取るか**
3. **顧客層を単店側に広げるか**（広げるならInstagramが最有力に戻る）
4. **顧客層を大手チェーン本部・大手卸に広げるか**（広げるならLinkedInが主戦場に昇格）
5. **登壇の機会を取りにいくか**（取るなら、この商売で最も効率が良い導線になる可能性が高い）

補足: 旬彩坊の委託業務に**「新規の営業」が含まれている**。つまり卸業界の営業網と面識を
既に自分で作っている状態で、登壇や業界の場に出る機会は外から作るより取りやすい。
この点もv2で活かせていなかった（確信度: 中）。
