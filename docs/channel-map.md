## 0. 結論

**媒体を増やす話ではありません。「確かめる材料」が存在しないのが、いま最大の穴です。**

紹介が契約の1位の経路なのに、紹介された人が社名を検索して確かめようとすると、材料が何も出てきません。

| 確かめる材料 | 現状 |
|---|---|
| 指名検索での実在性（構造化データ・第三者言及） | **不足**。JSON-LDに `sameAs` `logo` が無く、SNSと結びついていない |
| サイトの事例（数字入り） | **0本**。あるのは架空データのデモ15本 |
| 会社案内PDF | **事例なし**。「公開中の制作デモ」になっている（`assets/company-profile.html`） |
| SNSアカウントへのリンク | **LINEとnote以外は1つもない** |

**投稿を始める前に、ここを埋めるのが先です。** 確信度: 高

そして正直に言うと、**SNSを何個回しても、この規模では契約は直接生まれません**（確信度: 高）。
SNSの役割は「確かめたときに生きていると分かる」ことと「紹介の摩擦を下げる」こと。
契約を生むのは紹介と指名検索です。ここを取り違えると、必ず「効果がない」と判断して止めることになります。

## 1. 設計の骨格：5段階モデル

媒体を並べる前に、人がどう動くかを5段階に置く。

| 段階 | 人の状態 | この商売での重要度 |
|---|---|---|
| ① 出会う | 存在を知る | 中 |
| ② **確かめる** | 「この人で大丈夫か」を検証する | **最重要かつ現状で最も欠けている** |
| ③ 判断する | 事例・料金・進め方を見る | 高 |
| ④ 話す | 名指しの相談をする | 高 |
| ⑤ 続ける | 契約後。**紹介の源泉になる** | 最重要 |

```
⑤ 続ける ──→ ① 出会う（紹介） ──→ ② 確かめる ──→ ③ 判断する ──→ ④ 話す ──→ ⑤
     └──────────────── これがこの商売のエンジン ────────────────┘
```

**世の中のチャネル設計はほぼ①（認知）に向けて作られています。この商売のボトルネックは②です。**
①をいくら増やしても②が空なら、全部そこで止まります。

## 3. SNSの判定根拠（各プラットフォームを個別に）

### 3-1. Threads — 採用（v2で新規追加）

**特性**

- Instagramアカウントと紐づくので**即開設できる**。新規アカウントの育成期間が不要
- **フォロワー外に配るアルゴリズム。** フォロワー0でも初速が出る（確信度: 中）
- **リンクのクリック率がXより高い。** Xがリンク付き投稿のリーチを抑える傾向に対し、Threadsは比較的抑えない（確信度: 中）
- テキスト中心なので**画像制作コストがゼロ**
- 弱点: ビジネス層・経営層が薄い。検索性が弱くストックにならない

**Instagramと直接比較すると、同じ層を狙うのにThreadsの方が圧倒的に安い**

| | Instagram | Threads |
|---|---|---|
| 制作コスト | 高（カルーセル10枚の画像制作） | **ほぼゼロ（テキスト）** |
| 本文にリンク | **貼れない**（プロフィール1つのみ） | **貼れる** |
| 初速 | フォロワー数に依存 | **フォロワー外に配られる** |
| ターゲット | 個人店オーナー | 個人店オーナー＋幅広い |

→ 前回「Instagramをやらない」と判断したが、**その枠にThreadsを入れる**のが合理的。
狙う層は同じで、コストが1桁違い、しかもリンクが機能する。

### 3-2. Facebook — 置くだけ（v2の漏れを補完）

前回まったく触れていなかった。これは漏れです。

- **日本の40〜60代の経営者層が残っている。** 飲食・卸業界の経営者は50代前後が多く、この層はFacebookにいる（確信度: 中〜高）
- 実名制でリアルの人間関係に紐づくため、**紹介の裏取りに実際に使われる**
- ただし**投稿の拡散力はほぼ死んでいる**。発信媒体としては期待しない

正直に言うと、**ユーザー層（卸・多店舗の50代経営者）に対しては、FacebookのほうがLinkedInより濃い可能性があります**（確信度: 中）。
ただし発信が機能しないので「確かめる」枠に置き、**個人アカウントのプロフィールを整えるだけ**にする。
社名・事業内容・サイトURLを書いて放置。

### 3-3. LinkedIn — 転記のみ

- **食品卸・商社の食品部門・外食チェーン本部の経営/管理層はいる**（個人飲食店オーナーはいない）
- 「飲食 × データ × 流通」のニッチは競合がほぼゼロで、投稿が埋もれない
- 低volume・高signalという性質がN=3の商売に構造的に合う
- **新規に書かない。** noteの要約を転記するだけ（月0.5h）
- 確信度: 中（日本の食品卸セグメントの浸透率は検証できていない。工数0.5hなので外れても損は小さい）

### 3-4. Instagram — 置くだけ（投稿しない）

- ユーザー（卸の経営者・多店舗の役員）はInstagramで経営課題を探していない
- 構造的に本文にリンクが貼れないので導線が作れない
- 画像制作コストが高く、同じ層はThreadsで安く取れる

**プロフィールとハイライトだけ整えて、投稿は止める。** アカウントが存在して事例へのリンクがあれば、②の役目は果たす。

例外: 個人店〜数店舗のオーナー向けの仕事（単店の数字管理・SNS集客）を主戦場にするなら最有力に戻る。
つまりInstagramをやるかは**狙うユーザー層を単店側に広げるかという事業判断**で決まる。

### 3-5. X — 読む側専用

前回「業界ニュース自動取得（`.github/scripts/fetch_news.py`）があるから低工数」と書いたが、工数を測り直すと**月2〜3h**かかる。

その2〜3hはThreadsに回した方が導線として機能する（リンクが効く）。
加えて、業界内に既に人脈がある人にとってXは不要（直接会える）。
SNSが必要なのは**まだ知らない人**で、それにはThreadsの初速の方が効く。

→ **投稿しない。業界の空気を掴む読む側として使う。** 確信度: 中

### 3-6. YouTube — 集客ではなく営業資料として

集客チャネルとしては工数が重すぎるのでやらない。

ただし**ツールの操作説明動画は営業資料として極めて強い**。商談で見せる、メールに貼る、
卸がFC加盟店に説明するときに使える。

→ 「SNS」ではなく**営業資料**として2〜3本だけ作る。限定公開でよい。

### 3-7. TikTok — やらない

ユーザーがいない。飲食店の若手スタッフはいるが、決裁者ではない。

## 4. 指名検索と課題検索 ― 一度つけた優先順位を訂正する

**SEOには2種類ある。前回これを分けていなかった。**

| 種類 | 検索される言葉 | 何のため | 優先度 |
|---|---|---|---|
| **指名検索SEO** | 「株式会社スパイシーデバイス」「藤谷拓文」「スパイシーデバイス 飲食」 | **紹介の裏取り** | **最優先** |
| 課題検索SEO | 「店舗間 精算」「卸 受発注 効率化」「仕入れ 見える化」 | 新規獲得 | 2番目 |

**この優先順位は誤りだった。訂正する。**

| | 指名検索 | 課題検索 |
|---|---|---|
| 検索する言葉 | 「株式会社スパイシーデバイス」「藤谷拓文」 | 「飲食店 銀行融資 フォーマット」「2店舗目 出店」 |
| ボリューム | **年に数件レベル。ほぼ発生しない** | 月単位で実在する |
| 誰が検索するか | すでに名前を聞いた人だけ | **まだ藤谷を知らない人** |
| 判定 | **保険。獲得手段ではない** | **本丸** |

理由は2つ（確信度: 中〜高）。

1. 指名検索は、名前を聞いた人しか検索しない。紹介が年数件なら検索も年数件で、量として成立しない
2. 卸業界の紹介は「直接つなぐ」形が多い。LINEを交換して終わりで、**調べるステップ自体が挟まらない**

さらに構造的な話として、**検索ルートでは「社名で調べる」段階が存在しない。**
記事を読んだ時点で「この人は分かっている」の判定が終わるので、記事が②を兼ねる。

したがって **最優先は記事（課題検索の受け皿）**。`sameAs` の整備は15分で終わるので
「ついで」にやるが、優先度は下げる。

指名検索で出したいもの（上から順に）:

1. 自社サイトのトップ
2. **事例ページ**（数字入り）
3. 第三者からの言及（取引先サイト・業界メディア・登壇の告知ページ）
4. note（人柄）
5. LinkedIn / Facebook（実在の裏取り）

今はこのうち1しかなく、2〜5が全部ありません。

### Googleビジネスプロフィール（MEO）は見送る ― 当初の推奨を撤回

**理由1: シェアオフィスはGBPの規約上リスクが高い。**
同一住所に複数の事業者が並ぶため、停止（サスペンド）の典型パターンにあたる。
一度停止されると再開の手続きが面倒になる。確信度: 中〜高

**理由2: そもそも来店型の商売ではない。**
ユーザーが事務所を訪れることはないので、地図枠（ローカルパック）に出ても意味がない。
「飲食 コンサル 豊島区」で探すユーザーは存在しない。確信度: 高

**ただし「指名検索で実在性を示す」という目的自体は正しい。** 手段を差し替える。

| 手段 | 内容 | 工数 |
|---|---|---|
| **JSON-LD に `sameAs` を追加** | note/Threads/LinkedIn/Facebook/Instagram のURL配列。Googleが同一エンティティとして結びつける | 15分 |
| **JSON-LD に `logo` を追加** | `assets/logo.png` を指定 | 5分 |
| `@type` の見直し | 現在 `ProfessionalService`（LocalBusinessのサブタイプ＝実店舗を含意）。シェアオフィスなら `Organization` の方が正確 | 5分 |
| **第三者からの言及** | 取引先サイト・業界メディア・登壇の告知ページ。**実在性としては最強** | 変動 |
| SNSプロフィールの整合 | 全媒体で同じ社名・事業内容・URL。`sameAs` と一致させる | 2h |
| 法人番号公表サイト・gBizINFO | 法人番号は公開情報で自動掲載。**何もしなくてよい** | 0 |

工数はGBP登録（1h）より減って、効果は落ちない。確信度: 中〜高

現状（確認済み）: JSON-LDは `index.html` にあり `name` `url` `telephone` `founder` `address` 等は入っているが、
**`sameAs` `logo` `image` がいずれも無い。**

## 5. 実際に回すものの運用仕様（3つだけ）

### 5-1. note（母艦・月1本）

| | |
|---|---|
| 目的 | 考え方と現場を見せ、人柄の裏取りに耐える状態を作る |
| ゴール | 事例ページへの遷移。読んだ人が「この人なら分かっている」と思う |
| 型 | 現場の話・失敗談・業界への意見。既存6本の型をそのまま継続 |
| 文量 | 800〜1500字 |
| 末尾 | **事例ページへのリンク1本だけ** |
| 書かないこと | 売り込み、会社紹介、ツールの機能説明 |
| 判定テスト | 「これは人を知るための文章か」→ yes なら note |

既存9本に対して**一度だけやる作業**: プロフィール欄と各記事末に事例ページへのリンクを追記。

### 5-2. Threads（週2〜3・転記）

| | |
|---|---|
| 目的 | noteと事例の断片を撒いて、まだ知らない人に出会う |

| 素材 | note記事の一節、現場で気づいたこと一言、事例の数字ひとつ |
| 型 | テキスト1〜3行 ＋ リンク |
| 画像 | **作らない** |
| 書かないこと | 長文、連投スレッド、他人への論評、業界批判 |

### 5-3. LinkedIn（月1・転記）

| | |
|---|---|
| 目的 | 卸・商社・チェーン本部の管理層に存在を知らせる |
| ゴール | プロフィール閲覧、接続申請の承認 |

| 新規執筆 | **しない** |

### 5-4. プロフィール文言は全媒体で揃える

「あいだ」ポジションの一文を決めて、以下すべてに同じ文言を入れる。バラバラだと②で信頼が落ちる。

サイト / note / Threads / Instagram / LinkedIn / Facebook / 会社案内PDF / 名刺（＋JSON-LD の `description`）

| 14 | **サイトのフッターに全SNSリンクを置く**（今ゼロ） | 0.5h | ② |
| 15〜30 | note 1本 → Threads / LinkedIn に転記 | 3h | ① |

合計 約18h。

## 7. 測る / 測らない

### 測る

| 指標 | 目標 |
|---|---|
| 名指しの相談件数 | 月1件 |
| 紹介の発生件数 | 四半期1件 |
| 指名検索から事例ページに到達した数 | 増えていること |
| 公開した事例の本数 | 累計3本 |
| Threads / LinkedIn からサイトへのクリック | 月0でなければ可 |

### 測らない

**PV・フォロワー数・いいね・インプレッション・エンゲージメント率。**
N=3の商売では意思決定に使えません。追い始めた瞬間に工数が溶けます。

### 流入元を知る唯一の確実な方法

**フォームで直接聞く**（「どこで知りましたか」の選択式）。UTMとリファラは補助。確信度: 高

## 8. 見直し・撤退基準

| 媒体 | 基準 |
|---|---|
| 構造化データ | 一度入れたら終わり。SNSを増やしたときだけ `sameAs` に追記 |
| Threads | 3ヶ月でサイトへのクリックが月0なら止める |
| LinkedIn | 3ヶ月でプロフィール閲覧が月一桁なら転記も止める |
| note | **止めない。** 最も安く、人柄の裏取りに必須 |
| Instagram / Facebook | プロフィールのみなので見直し不要 |
| 全体 | **6ヶ月で名指し相談が0なら、SNSを全部止めて紹介と登壇に全振りする** |
